# Mục lục tài liệu AELC

Thư mục này là nguồn tham chiếu chuẩn khi triển khai AELC. Coding agents phải đọc `../AGENTS.md` trước khi thực hiện công việc.

| File | Nội dung |
|---|---|
| [01 — Project charter](01-project-charter.md) | Định nghĩa, đối tượng sử dụng, kỳ vọng thành công và non-goals. |
| [02 — Objectives](02-objectives.md) | Mục tiêu đã thống nhất và định hướng đo lường. |
| [03 — Scope và use cases](03-scope-and-use-cases.md) | Bốn tình huống SDLC; chi tiết workflow để phát triển sau. |
| [04 — Principles và responsibility](04-principles-and-responsibility.md) | Productivity và human understanding; AI evidence và human ownership. |
| [05 — System architecture](05-system-architecture.md) | Ranh giới và ownership giữa framework, project, user, harness và external systems. |
| [06 — Repository structure](06-repository-structure.md) | Cây thư mục mục tiêu, phần của MVP và quy tắc đóng gói resources. |
| [07 — Installation và lifecycle](07-installation-and-lifecycle.md) | Setup, global install, project init, update, migration và uninstall. |
| [08 — Identity và membership](08-identity-and-membership.md) | Authenticated mapping, self-declared fallback, role và activity attribution. |
| [09 — Knowledge và evidence](09-knowledge-and-evidence.md) | Project/role/member knowledge, demonstrated understanding, coverage và freshness. |
| [10 — Capabilities và integrations](10-capabilities-and-integrations.md) | Interface sẵn sàng cho MCP, tool authorization và provenance. |
| [11 — MVP v0.1](11-mvp-v0.1.md) | Deliverable đầu tiên, acceptance criteria và các phần chưa triển khai. |
| [12 — Engineering guidelines](12-engineering-guidelines.md) | Chất lượng code, testing, safe defaults và các ràng buộc thiết kế. |
| [13 — Decisions và open questions](13-decisions-and-open-questions.md) | Định hướng đã thống nhất và những lựa chọn còn cần quyết định. |
| [14 — Glossary](14-glossary.md) | Thuật ngữ thống nhất khi viết code, docs và hướng dẫn agent. |

**Quy ước trạng thái:** “Đã thống nhất” là intent được xác nhận trong thảo luận thiết kế; “đề xuất” là một phương án implementation; “chưa quyết định” cần lựa chọn rõ ở bước sau. Không được xem diagram hoặc ví dụ stage trong overview là workflow specification đã chốt.
